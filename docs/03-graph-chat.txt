Features to document:

Add a read-only Graph Chat assistant in Components/Pages/GraphChat.razor. The
application already has a singleton GraphStore containing Ticket, TicketDetail,
Requester, Status, and Day nodes and REQUESTED_BY, HAS_DETAIL, HAS_STATUS, and
OCCURRED_ON edges. The new page should answer relationship questions about this graph
at /graphchat. Typical questions include "How many tickets has this email opened?",
"List the open tickets," and "Show graph statistics."

The assistant must remain strictly read-only and ground every answer in deterministic
GraphStore traversals exposed as tools. It must never invent ticket IDs, email
addresses, counts, statuses, or dates. Use Microsoft.Extensions.AI, including
IChatClient and automatic function invocation, and use Syncfusion's Blazor
SfAIAssistView for the interface.

Create Services/AI/ChatClientFactory.cs to keep OpenAI client construction behind
IChatClient. Its static Create(IConfiguration aiSection) method should read ApiKey and
Model from the "AI" section and fall back to a DefaultModel constant when Model is
absent. OpenAI is the only supported AI provider; do not add a provider selector.

Build the client against the OpenAI Responses API rather than Chat Completions:
new OpenAIClient(apiKey).GetResponsesClient().AsIChatClient(model). This matters,
because reasoning models such as the gpt-5 family reject function tools on
/v1/chat/completions but accept them on /v1/responses. The Responses client is still
marked experimental in the OpenAI SDK, so the call site needs a
#pragma warning disable OPENAI001 and restore pair with a comment explaining why.
Finish the pipeline with .AsBuilder().UseFunctionInvocation().Build() so tool calls
are handled automatically during a chat request.

Do not make a configured API key a startup requirement. The application and chat page
must still load when the key is empty; substitute a placeholder key so construction
does not throw, and let an attempted request fail with a clear authentication message
surfaced by the page.

The "AI" section is the single AI configuration for the whole application. It holds
ApiKey and Model and nothing else. There is no separate "OpenAI" configuration
section: Program.cs reads AI:ApiKey and AI:Model directly to register the Syncfusion
Smart Components inference service, and only when the key is non-empty. Document that
one section feeding two consumers, so nobody reintroduces a second key.

Define the read-only tool contract in Services/AI/GraphTools/IGraphChatTools.cs and
implement it in GraphChatTools.cs. Every method should perform a deterministic
GraphStore traversal and have a [Description] attribute so its method signature can
become the tool schema. Put the [Description] attributes on the interface rather than
the implementation, so the text the model reads and the contract the code compiles
against cannot drift apart. Any method that returns a list must accept a max argument
to keep results from flooding the model's context window.

Provide these tools: FindRequesterByEmail(query, max),
CountTicketsForRequester(email), ListTicketsForRequester(email, status, max),
ListDetailsForTicket(ticketId, max), SearchNodes(query, type, max), GetNode(id),
GetNeighbors(id, edgeType, max), and Stats(). They are all read-only. Return focused
DTOs, declared in Services/AI/GraphTools/GraphChatDtos.cs, such as NodeSummary,
NodeDetail, Neighbor, TicketSummary, CommentSummary, RequesterSummary, and GraphStats,
rather than raw graph nodes or database rows.

In Services/AI/GraphTools/GraphToolRegistration.cs, add a static
CreateTools(IGraphChatTools) method. It should wrap every method with
AIFunctionFactory.Create and return IList<AITool>.

Services/AI/GraphTools/GraphSystemPrompt.cs should expose a constant prompt that
