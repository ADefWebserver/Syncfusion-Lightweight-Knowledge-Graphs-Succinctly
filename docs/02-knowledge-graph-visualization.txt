Features to document:

Feature: The Knowledge Graph Visualization page (Components/Pages/Graph.razor).

Context:
The application already has a file-based knowledge graph loaded into a singleton
GraphStore (nodes and edges with types Ticket, TicketDetail, Requester, Status, Day,
and edges REQUESTED_BY, HAS_DETAIL, HAS_STATUS, OCCURRED_ON). This feature adds an
interactive Blazor Server page that renders that graph visually in the browser using
Cytoscape.js through JavaScript interop. Assume GraphStore and HelpDeskGraphBuilder
already exist and are registered in DI.

Goal:
Build an interactive graph explorer at route /graph that draws the knowledge graph,
lets the user filter by node type, click a node to inspect its properties and
neighbors, and rebuild the graph from the current database, all without a page
reload.

What to document and design:

1. The JavaScript renderer (wwwroot/js/graph-renderer.js):
   - Load Cytoscape.js (wwwroot/js/cytoscape.min.js) and reference it from the app host.
   - A node-type style map giving each type a distinct color and shape
     (Ticket = blue round-rectangle, TicketDetail = green ellipse, Requester = red
     ellipse, Status = orange diamond, Day = teal rectangle).
   - Edge styling with a label, arrowhead, and bezier curve style; a :selected style.
   - A "cose" force-directed layout with animation.
   - Exported functions callable from Blazor: initCytoscape(containerId, graphData,
     dotNetRef), updateGraph(containerId, graphData), destroyCytoscape(containerId),
     and toggleFullScreen(containerId). initCytoscape wires a node tap handler that
     calls back into .NET (OnNodeClicked) and a background tap that clears selection.

2. The Blazor page (Components/Pages/Graph.razor):
   - @page "/graph", @rendermode InteractiveServer, @implements IAsyncDisposable.
   - Inject IJSRuntime, GraphStore, and HelpDeskGraphBuilder.
   - Toolbar: a Rebuild Graph button (disabled while busy), badges showing node and
     edge counts, the generated timestamp, and a Full Screen toggle.
   - Entity-type checkboxes built from GraphStore.NodeTypes. Default the
     visible set to the connected core (Ticket + Requester + Status) and let the user
     toggle the busier types (TicketDetail, Day) on; fall back to showing all types if
     none of the defaults are present.
   - A #cy container div sized to the viewport, plus a detail panel that appears when a
     node is selected showing its label, type, all Data properties, and a list of
     connected nodes with the relationship label.

3. The interop and data shaping:
   - BuildGraphData(): project only nodes whose type is visible, and only edges whose
     both endpoints are visible, into a shape of { nodes:[{id,label,type}],
     edges:[{id,source,target,label}] } that the renderer expects.
   - OnAfterRenderAsync(firstRender): on first render, create a DotNetObjectReference
     and call initCytoscape.
   - [JSInvokable] OnNodeClicked(nodeId): look the node up in GraphStore, populate the
     detail panel metadata, and gather neighbors from OutEdges and InEdges.
   - ToggleType: update the visible set, dismiss the panel, and call updateGraph
     (re-render without re-initializing).
   - RebuildAsync: call HelpDeskGraphBuilder.BuildAsync(), GraphStore.ReloadAsync(),
     refresh the type list, and re-initialize the diagram.
   - DisposeAsync: call destroyCytoscape and dispose the DotNetObjectReference; swallow
     JSDisconnectedException when the circuit is already gone.

4. Configuration note:
   - Large graphs can produce big interop payloads, so raise the SignalR hub message
     size limit in Program.cs (AddInteractiveServerComponents / HubOptions
     MaximumReceiveMessageSize) so a big graph does not drop the circuit.
