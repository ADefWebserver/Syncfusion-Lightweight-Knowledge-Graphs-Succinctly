Features to document:

Feature: The Graph Chat assistant with mutations (Components/Pages/GraphChat.razor
extended with a safe write path and human approval).

Context:
The application already has (a) a file-based knowledge graph under App_Data/graph with
a GraphStore in memory, and (b) a read-only chat page at /graphchat that answers
questions by calling deterministic graph tools through Microsoft.Extensions.AI. This
feature adds the ability to CHANGE the graph, but only through a controlled,
audited, two-phase path that a human must approve. It also introduces an optional
"knowledge layer" of graph-native nodes and edges that do not come from the database.

Goal:
Let the assistant propose changes to the graph and apply them only after a preview and
an explicit human approval, so the database-derived facts stay read-only while a
curated knowledge layer can be edited safely.

What to document and design:

1. The extended knowledge domain (graph-native, not from the database):
   - New node types: KnowledgeArticle and Resolution.
   - New edge types: LINKED_TO (Ticket -> Ticket), REFERENCES_ARTICLE
     (Ticket -> KnowledgeArticle), RESOLVED_BY (Ticket -> Resolution).
   - These are the only things that may be created, edited, or deleted; the
     database-derived nodes (Ticket, TicketDetail, Requester, Status, Day) remain
     strictly read-only.

2. The mutations specification (specs/mutations.md):
   - Every mutation tool has the signature pattern
     MutationResult Name(args, bool confirmed = false).
   - When confirmed == false the tool changes NOTHING and returns a MutationResult
     whose Preview holds a human-readable summary, the list of files that would change,
     and any validation warnings. When confirmed == true it applies the change,
     rebuilds indexes, updates the manifest, appends to the audit log, and returns the
     post-change state.
   - Document the tool set and validation rules: LinkTickets (add LINKED_TO; reject a
     duplicate in either direction and self-links), AddKnowledgeArticle (create a
     KnowledgeArticle node), ReferenceArticle (add REFERENCES_ARTICLE; reject if it
     already exists), RecordResolution (create a Resolution node plus a RESOLVED_BY
     edge), DeleteArticle (remove an article and its incoming edges; reject while a
     REFERENCES_ARTICLE still points to it unless cascade == true). Both endpoints of
     any new edge must exist and be of the expected type. Mutations targeting
     database-derived node properties are rejected.

3. The mutation models (Services/Graph/MutationModels.cs):
   - MutationStatus enum (Rejected, PreviewOnly, Applied).
   - MutationPreview (Summary, AffectedFiles, Warnings).
   - MutationResult (Status, Preview, Errors) with Rejected/PreviewOnly/Applied
     factory helpers.

4. The single writer (Services/Graph/GraphMutationService.cs):
   - The ONLY component allowed to write the graph files. Guard writes with a
     SemaphoreSlim so two mutations cannot interleave.
   - Keep a ReadOnlyNodeTypes set (Ticket, TicketDetail, Requester, Status, Day) and
     reject any mutation that targets them.
   - Each public mutation follows the two-phase pattern above. On confirm it applies
     the change to an in-memory GraphDocument, writes graph.json and manifest.json
     atomically (temp file then move), refreshes GraphStore, and appends a line to
     audit.log.
   - Include UpdateNodeContent(nodeId, propertyName, value, confirmed): set one Data
     property of an existing node, or its label when propertyName == "label". It never
     creates or deletes nodes and never touches edges, and rejects read-only nodes.

5. The chat write tool (Services/AI/GraphTools/IGraphWriteTools.cs and
   GraphWriteTools.cs):
   - Expose exactly ONE write capability to the model: UpdateNodeContent(nodeId,
     propertyName, value), delegating to GraphMutationService with confirmed = true
     only after human approval. The [Description] must make clear this is the only
     permitted change, that it cannot create or delete nodes or edges, and that
     database-derived nodes are read-only.
   - Extend GraphToolRegistration with an overload CreateTools(read, write) that adds
     the write tool alongside the read-only traversal tools.
   - Update GraphSystemPrompt to describe the optional knowledge layer and the single
     write tool, instructing the model to change a node's contents only when the user
     clearly asks and to report exactly what the tool returns.

6. The approval UI (Components/Shared/MutationApproval.razor):
   - A Syncfusion SfDialog (modal) that shows the MutationPreview (the summary, the
     list of affected files, and any warnings) with Approve and Reject buttons and
     Visible / VisibleChanged, Preview, OnApprove, and OnReject parameters.
   - Wire GraphChat.razor so a proposed change first produces a preview
     (confirmed = false), displays the approval dialog, and only calls the mutation
     with confirmed = true when the user approves; on reject, nothing is written.

7. Dependency injection (Program.cs):
   - Register GraphMutationService (scoped) and IGraphWriteTools -> GraphWriteTools,
     and pass both the read and write tools into the chat's tool list.

8. Main-menu integration:
   - This feature extends the existing /graphchat page, so the "Graph Assistant" sidebar
     link and its icon were already added with the read-only chat (feature 3); no new
     menu item is required here. If the entry is not yet present, add it in
     Components/Layout/NavMenu.razor and, because this template does NOT load a Bootstrap

Diagrams to include:

Acceptance criteria to list:
- A preview call (confirmed == false) never writes to disk.
- No change is applied until the human clicks Approve in the dialog.
- Database-derived nodes cannot be edited; such attempts are rejected with a clear
  message.
- Duplicate LINKED_TO and REFERENCES_ARTICLE edges are rejected; DeleteArticle is
  rejected while an article is still referenced unless cascade is set.
- Every applied mutation writes graph.json and manifest.json atomically and appends one
  line to audit.log.
